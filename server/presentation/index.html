Key Features Phase 3

📊 Charts

Claude derives data from log lines and renders bar, line, or pie charts automatically when the answer is comparative or time-series.

🗂 Source Attribution

Every answer shows which log files matched, on which machines, with line counts. Click to expand the file list.

💬 Rich Answers

Markdown rendering — tables, code blocks, bold. Claude returns structured summaries, not raw grep output.

⚠️ Anomaly Detection

If logs contain SIGTERM, crashed, or shutdown, Claude flags it prominently at the top of the answer — even when not asked.

🔍 Arbitrary Paths

"Search /var/log/custom.log on server1" — agent routes to the right sidecar and passes the path directly. No pre-registration needed.

👍 Feedback Loop

Thumbs up/down with optional comment on every answer. Persisted in DB for monitoring answer quality over time.

Security & Reliability

Security

  • Read-only sidecars — can only read files where they have filesystem permission
  • No shell execution — pure file reads, no remote code execution surface
  • Secrets never in config files — API keys only in .env (gitignored)
  • Systemd hardening — NoNewPrivileges, PrivateTmp, ProtectSystem=strict
  • Phase 4: auth tokens between server ↔ sidecar + TLS

Reliability

  • Graceful degradation — if a sidecar is unreachable, the answer notes it and continues with available data
  • Dead sidecar detection — background task marks sidecars dead if no heartbeat in 60s
  • 10s per-sidecar timeout — slow machines don't block the whole query
  • Conversation persistence — full history in Postgres, survives server restarts
  • Parallel fanout — all sidecars queried concurrently via asyncio
